# Source release process

Paperplane follows Semantic Versioning and publishes source-only GitHub releases from
`main`. It is not built or published as a PyPI package.

## Version sources

The release script synchronizes exactly these files:

- `pyproject.toml` — project version;
- `uv.lock` — locked project metadata;
- `streamlit_app.py` — visible `APP_VERSION`; and
- `CHANGELOG.md` — dated release section.

Other documentation is not generated by the release script. Before releasing, manually
confirm that `README.md`, `docs/RELEASE_NOTES.md`, `Zero_to_Hero_Study_Handbook.md`, and all
affected setup, capability, architecture, and limitation pages describe the shipped code.

Use a major bump for a breaking public contract change, a minor bump for new user-visible
functionality, and a patch bump for compatible fixes or documentation corrections. The
script accepts only strict `X.Y.Z` versions; prerelease suffixes are not supported.

## 1. Preflight

Work from a clean `main` worktree with authenticated `git` and `gh` access. Confirm the
intended changes and run the release checks:

```powershell
git branch --show-current
git status --short
uv sync --locked --extra cpu --extra test --extra lint --extra docs
uv run ruff check paperplane app_pages tests streamlit_app.py workspace_app.py scripts
uv run ruff format --check paperplane app_pages tests streamlit_app.py workspace_app.py scripts
uv run pyright
uv run pytest tests -q
uv run python scripts/build_handbook.py
uv run python scripts/build_app_guide.py
git diff --exit-code -- docs/APP_CAPABILITIES.html
gh auth status
```

Smoke-test the actual app: confirm the four vertical sidebar toggles are exclusive, upload
multiple files with independent ranges, Parse, switch the shared document selector across
all six full-width tabs, switch both JSON formats, download each selected-document artifact,
and inspect the batch ZIP manifest and safe per-document folders:

```powershell
uv run --extra cpu streamlit run workspace_app.py --server.port=8551
```

## 2. Preview the release

A dry run prints the current and proposed versions without editing files:

```powershell
uv run python scripts/release.py --bump patch --dry-run
```

Choose exactly one version option:

```text
--bump major|minor|patch
--version X.Y.Z
```

Provide concise release notes with `--notes`. Without `--push`, the script updates the
four version sources but does not commit, tag, push, or create a GitHub release:

```powershell
uv run python scripts/release.py --bump minor --notes "Release summary"
git diff -- pyproject.toml uv.lock streamlit_app.py CHANGELOG.md
```

Review those edits before committing them manually or restoring them through a normal,
non-destructive edit if the release is not ready.

## 3. Publish

Run the publishing form only when the worktree is clean. The script refuses `--push` when
any tracked or untracked change is present.

```powershell
uv run python scripts/release.py --bump minor --notes "Release summary" --push
```

The script then:

1. updates `pyproject.toml`, `uv.lock`, `streamlit_app.py`, and `CHANGELOG.md`;
2. commits them as `chore(release): X.Y.Z`;
3. creates annotated tag `vX.Y.Z`;
4. pushes `main` and the tag to `origin`; and
5. creates the GitHub release with `gh`.

The remote and branch are currently fixed to `origin` and `main`.

## 4. Verify the published release

```powershell
git show --stat vX.Y.Z
gh release view vX.Y.Z
git status --short
```

Confirm the release notes render correctly, the tag targets the release commit, CI passes
on `main`, and a clean checkout of the tag launches with `Paperplane.cmd`.
